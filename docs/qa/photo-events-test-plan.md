## 4. Visual regression

- **Goldens:** one PNG per (layout, size, side) in `boxes` text mode (no font dependency), rendered at 100 DPI to keep the repo small, plus one 300 DPI golden per Phase 1 layout. Fixed synthetic photos and a fixed design JSON per golden.
- **Compare:** `pixelmatch` threshold 0.1, fail when more than 0.1 % of pixels differ. Sharp/libvips builds differ between Windows and Linux CI, so goldens are generated on CI Linux; local Windows runs report but don't fail.
- **Text in print:** a second set renders through `layout/flat.ts` and rasterises the PDF, so font changes show up too. Fonts are fixed TTFs in the repo, so this is stable.
- **Updating goldens:** only with `UPDATE_GOLDENS=1` in a commit that says why; the diff images go in the PR, never real photos.
- **What visual regression does not catch:** colour on paper. That is the physical proof (owner orders, Fulfillment judges against a checklist: trim drift, colour cast, text sharpness at 8.5 pt, scrim legibility).
