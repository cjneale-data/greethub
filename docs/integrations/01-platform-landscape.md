## 1. The protocol layer: MCP

**Spec version.** Latest revision is **2026-07-28**, released 2026-07-28; the previous "legacy" revision is 2025-11-25. [V] https://modelcontextprotocol.io/specification/latest ; [V] https://blog.modelcontextprotocol.io/posts/2026-07-28/ ; [S] https://workos.com/blog/mcp-2026-spec-agent-authentication.

What changed that matters to us ([V] blog and spec pages):
- **Stateless core.** No `initialize` handshake and no `Mcp-Session-Id`; every request carries protocol version, client identity and capabilities in `_meta`. Servers needing state hand out explicit handles (the spec's own example is a shopping basket id). This fits us: `draft_id` and `approval_id` are handles bound server-side to the authenticated user (state-handle hijacking guidance, [V] https://modelcontextprotocol.io/docs/tutorials/security/security_best_practices).
- **Transport.** Streamable HTTP; requests carry `Mcp-Method` and `Mcp-Name` headers; legacy HTTP+SSE deprecated with a year-long off-ramp. Copilot Studio already dropped SSE (Aug 2025) [V].
- **Tools.** `inputSchema`, optional `outputSchema`, `structuredContent` (server should also return the JSON as text for compatibility), `annotations`, `title`, `icons`. The tools/list result may vary with the caller's authorization (we use this to hide autonomy tools). Errors are either protocol errors or `isError: true` tool results the model can recover from. Clients MUST treat annotations as untrusted unless the server is trusted. The spec says there SHOULD be a human in the loop able to deny tool calls. [V] https://modelcontextprotocol.io/specification/latest/server/tools
- **Elicitation.** Form mode (flat primitives only; must not ask for passwords, keys or payment credentials) and URL mode (out-of-band, for auth and payments). In 2026-07-28 elicitation travels in "multi round-trip requests" (`resultType: input_required`, client retries with `inputResponses`). [V] https://modelcontextprotocol.io/specification/latest/client/elicitation . Client support is uneven [U]; we do not depend on it.
- **Tasks** (long-running work with polling) moved to an optional extension; **MCP Apps** (inline UI) is an extension; both opt-in. [V] spec overview.
- **Authorization (HTTP).** Optional in the spec but mandatory for us. The MCP server is an OAuth 2.1 resource server and MUST publish Protected Resource Metadata (RFC 9728); clients MUST send `resource` (RFC 8707) and PKCE; servers MUST validate token audience; client registration priority is Client ID Metadata Documents (CIMD, SHOULD), pre-registration, then Dynamic Client Registration (DCR, now deprecated but supported); `iss` validation (RFC 9207); insufficient-scope step-up via 403 `WWW-Authenticate`; access tokens never in the query string. [V] https://modelcontextprotocol.io/specification/latest/basic/authorization
- Alexa+ pins to **2025-11-25** [V] https://developer.amazon.com/docs/alexaplus/add-ons/mcp-toolkit-overview.html, so GreetHub must serve both revisions for now. Vercel's `mcp-handler` 2.1.1 with MCP server SDK v2 is the documented path [V] https://vercel.com/docs/mcp/deploy-mcp-servers-to-vercel (last updated 2026-09-18); whether it serves 2025-11-25 clients is not stated (spike in AGT-012).

## 2. Platform by platform

### ChatGPT (OpenAI): apps/plugins on MCP
- **How it consumes tools.** Remote MCP servers via the Apps SDK. Docs and the help center now say "plugin" and "app" interchangeably (naming in flux). Users add a custom server at chatgpt.com/plugins > plus > "Add custom MCP server" (public URL or tunnel, auth, risk warning, "Create as a plugin"), then type `@` to use it [V] https://developers.openai.com/apps-sdk/deploy/connect-chatgpt . Plan availability for custom servers is disputed across blogs (Plus/Pro/Business/Enterprise/Edu; some say write tools only on Business) [S] https://peliqan.io/blog/chatgpt-mcp/ ; not confirmed on a primary page. Workspace admins can restrict custom servers [V].
- **Auth.** OAuth 2.1 with PKCE (S256 must be advertised), protected resource metadata, CIMD preferred or DCR; redirect URI `https://chatgpt.com/connector_platform_oauth_redirect`; `resource` goes into the token audience; tokens verified on every request; per-tool `securitySchemes` (`noauth`, `oauth2` plus scopes); the linking UI triggers when a tool returns an error with `_meta["mcp/www_authenticate"]`. **ChatGPT does not support client credentials, service accounts or custom API keys.** It can present an OpenAI client certificate (mTLS) and publishes egress IP ranges. [V] https://developers.openai.com/apps-sdk/build/auth
- **Directory listing requirements.** Verified individual/organization (OpenAI Platform Business Verification) [S], production HTTPS `/mcp`, domain verification [S], OAuth with a reviewer demo account (sign-up-required or 2FA-gated demo accounts are rejected) [V], explicit booleans for `readOnlyHint`, `destructiveHint`, `openWorldHint` on every tool [V], CSP declarations for widgets/iframes [V], privacy policy and support contact [V], five positive and three negative test cases [S]. Review time "3 to 7 business days" is a third-party estimate [S] https://flowlines.ai/blog/how-to-get-listed-openai-plugin-directory . The official help article (help.openai.com/en/articles/20001040) returned 403, so portal steps are secondary.
- **Commerce rules** ([V] https://developers.openai.com/apps-sdk/app-submission-guidelines):
  - Commerce is allowed **for physical goods only**. Digital products, subscriptions, tokens and credits are not allowed, including freemium upsells.
  - Use external checkout on the merchant's own domain. Instant Checkout is a beta limited to select marketplace partners. No third-party checkout may be embedded in the plugin UI. "Linking directly to a checkout or transactional page is prohibited."
  - Never collect PCI data, credentials or government ids; minimize data; privacy policy required.
  - Annotations "do not replace ... human confirmation for irreversible operations."
  - Consequences for GreetHub: mailed cards (physical) are in scope; **digital cards and digital books are not purchasable via ChatGPT**; **no wallet top-ups or credits via ChatGPT**; the approval link should not be a bare checkout link inside ChatGPT. Design answer: approval happens through GreetHub's own push/email/app, the tool result says "Approval request sent", and the link is shown only on clients where it is allowed (decided per OAuth client id). What "linking directly to a checkout" means for an approve-then-pay page is ambiguous: ask OpenAI (09).
- **Instant Checkout / ACP status.** Reports say OpenAI scaled back Instant Checkout in March 2026 with fewer than 30 merchants live, while the ACP protocol survives [S] https://agenticcommerceprotocol.info/instant-checkout , https://www.laioutr.com/en/blog/chatgpt-instant-checkout-merchant-adoption-agentic-readiness-2026 . OpenAI's own policy page still calls it a beta for select partners [V]. Treat as unavailable.
- **Scheduled/automatic runs.** ChatGPT scheduled tasks were rebuilt in June 2026 and can reach connected apps; event triggers reported for Gmail, Slack, GitHub, not calendar [S] https://www.technology.org/2026/08/26/chatgpt-scheduled-tasks-free-accounts-triggers/ , https://porteden.com/blog/chatgpt-scheduled-tasks-tools/ (vendor blog, biased). A "meeting ended" trigger on ChatGPT probably needs a scheduled task that polls the calendar [U].
- **GPT Actions (OpenAPI).** Not found in current docs; do not plan on it.

### Claude (Anthropic): connectors and remote MCP
- **How it consumes tools.** Remote MCP servers are "connectors" across claude.ai, Desktop, mobile, Claude Code and Cowork; custom connectors by URL, or the Connectors Directory (Customize > Connectors). On Team/Enterprise an Owner adds the connector and members connect their own accounts (members can "Request"). [V] https://claude.com/docs/connectors/directory
- **Auth.** OAuth 2.0 with DCR or CIMD (CIMD is used only if the authorization server advertises `client_id_metadata_document_supported` and `none` in `token_endpoint_auth_methods_supported`); PKCE S256 on every request; hosted callback `https://claude.ai/api/mcp/auth_callback`, Claude Code loopback on any port; a 401 with `resource_metadata` is required (a header on a 200 is ignored); only the first `authorization_servers` entry is used; 10 s limit on discovery/registration/token endpoints and 30 s on refresh; refresh tokens must rotate for public clients; `client_credentials` not supported; static header credentials only in beta for limited orgs; Anthropic egress range `160.79.104.0/21`. [V] https://claude.com/docs/connectors/building/authentication
- **Directory requirements.** Paid Claude plan to submit (sources disagree on Team-only; the official page says any paid plan) via claude.ai/directory/manage; HTTPS remote server; every tool has a `title` and `readOnlyHint` or `destructiveHint`; OAuth for account access; privacy policy URL, docs URL, support contact, reviewer test account (fully populated); seven compliance acknowledgments including "financial transactions", "AI media generation" and "prompt injection". Automated scan, then listing as a **Community** connector by default; some are escalated to human **Verified** review, which is slower; no review time published. Escalations: mcp-review@anthropic.com. [V] https://claude.com/docs/connectors/building/submission , https://claude.com/docs/connectors/building/review-criteria
- **Rules that hit GreetHub** ([V] https://support.claude.com/en/articles/13145358-anthropic-software-directory-policy and the review criteria):
  - Section 4A bars "software that transfers money ... or other financial assets" and software that executes financial transactions for users, unless Anthropic expressly permits in writing. Review criteria list money transfer as unsupported. Whether buying a card from the merchant that runs the connector counts is **not stated**: ask.
  - Section 4B prohibits software that uses AI models to generate images, video or audio; design tools are allowed, and servers may generate images "within a design workflow, provided standalone image generation is not their primary service". GreetHub's product is AI-illustrated cards, so a reviewer could class the connector as AI media generation. Ask.
  - Tool design: separate read and write tools (no catch-all), names 64 characters or fewer, descriptions must not instruct Claude beyond the tool's function, no data collection beyond need, no querying chat history.
- **Scheduled/autonomous.** Claude Code "Routines" run saved prompts with connectors on Anthropic's cloud on a schedule, API call or GitHub event; research preview [S] https://makerkit.dev/blog/tutorials/claude-code-routines-guide (no official page found). Calendar trigger not found.

### Gemini (Google)
- **Consumer Gemini app.** Custom apps (MCP servers) via gemini.google.com > Settings > Connected Apps > Add a custom app > paste the URL. **Setup is web only**, then it works on mobile; requires 18+, **US only**, a **personal Google account** (not work/school), Keep Activity on, English only; auth via DCR or manually entered client credentials; Gemini "requires manual confirmation for any write actions"; Google "does not control, monitor, or secure third-party MCP servers" and warns Gemini may share chat content and other connected sources with the app. [V] https://support.google.com/gemini/answer/17209137
- **Gemini Enterprise.** Custom MCP server data store in the Business edition [S] https://docs.cloud.google.com/gemini/enterprise/docs/connectors/custom-mcp-server/set-up-custom-mcp-server (not fetched). Workspace MCP integrations (Asana, Atlassian, HubSpot, Mailchimp, QuickBooks, Monday, Salesforce) were added Sept 2026, partner-managed through the Marketplace [S] https://workspaceupdates.googleblog.com/2026/09/connect-to-more-tools-with-gemini-in-Google-Workspace.html .
- **Listing/approval.** No public submission process for the consumer app found (not found). One blog says custom connections are gated to "Gemini Spark" [S] https://findskill.ai/blog/gemini-spark-mcp-connector-roadmap/ ; it conflicts with the Google help page, so trust the help page.
- **Implication.** Data minimization must be enforced by GreetHub's server because Gemini may pass more context than the tool needs (04).

### Microsoft Copilot
- **Copilot Studio** (makers and enterprises): add an MCP server to an agent via the onboarding wizard (name, description, URL, auth None / API key (header or query) / OAuth 2.0 with dynamic discovery, dynamic or manual); Streamable transport only; governed by Power Platform data policies; alternative is a custom connector from an OpenAPI/Swagger file with `x-ms-agentic-protocol: mcp-streamable-1.0`. [V] https://learn.microsoft.com/en-us/microsoft-copilot-studio/mcp-add-existing-server-to-agent (updated 2026-08-19). The wizard offers API key in the query string, which violates MCP guidance; GreetHub will not support it.
- **Microsoft 365 Copilot declarative agents** can use MCP servers via the Agents Toolkit (public preview announced at Ignite 2025) and distribute through Partner Center validation [S] https://devblogs.microsoft.com/microsoft365dev/?p=25124 ; one blog claims a direct certification path for verified publishers [S] https://tallyfy.com/how-to-list-mcp-server-microsoft-copilot/ . Tenant admins can register a BYO MCP server in the Microsoft 365 Admin Center [V, same Learn page].
- **Consumer Copilot app:** how it consumes third-party tools or MCP was **not found**. For now Copilot is a business-user route, not a consumer one.
- **Licensing note.** One source says MCP tool calls consume Copilot Credits [S] https://www.stackone.com/blog/best-mcp-gateway-for-copilot-studio/ .

### Anything that comes next
Design rule: any new assistant will almost certainly support (a) MCP over Streamable HTTP with OAuth, or (b) an OpenAPI import. Keeping the contract in Zod with generated JSON Schema and OpenAPI covers both without new work.

## 3. What a non-technical customer must do to connect

Today (custom connection, no directory):
1. Sign in to greethub.com and open **Settings > Connected assistants > Connect an assistant** (to be built, AGT-007 and AGT-020).
2. Pick the assistant. The page shows the server URL with a copy button and numbered steps for that assistant, with screenshots.
3. In the assistant, add the connector by URL: ChatGPT: chatgpt.com/plugins > Add custom MCP server [V]; Claude: Customize > Connectors > add custom connector [V]; Gemini: Settings > Connected Apps > Add a custom app, on the web [V]; Perplexity: Connectors > Custom connector [S].
4. The assistant opens a GreetHub sign-in and consent screen showing the assistant's name, the permission level (Draft only / Draft and ask me / Send within limits) and the limits. The user signs in with their normal GreetHub login and approves.
5. Back on the GreetHub page, a "Send a test" button triggers a harmless `get_account_limits` call and shows it in the activity feed.

Honest assessment: step 3 is a developer-grade hurdle (pasting URLs; developer mode on some ChatGPT plans). Mass-market reach needs directory listings (P4), where it becomes "find GreetHub, press Connect, sign in". Until then, market this to early adopters only. Claude Team/Enterprise members may need an Owner to enable the connector first [V].
